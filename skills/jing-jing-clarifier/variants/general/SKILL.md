# JING JING Clarifier（晶晶體修飾器）一般版

## 目標

- 統一中文主體文本中的中英混寫。
- 將可明確對映的技術術語改為自然繁體中文。
- 不改變原文的事實、邏輯、數值與精準技術字串。

## 作業流程

1. 標示英文專有詞、術語短語與單個英文功能詞。
2. 只在一般敘述文字中，將不屬於受保護名稱、引用、命令、程式碼或識別碼的 `and`、`or`、`with`、`for`、`on`、`in`、`of`、`to`、`from`、`is`、`are` 等英文功能詞改為中文。
3. 將可對映的技術術語中文化；有必要時使用「英文詞[中文]」。
4. 重組為自然的繁體中文句子。
5. 回傳完整修訂版；若有歧義，採最保守的解釋並註明假設。

## 保留規則

保留專案、服務、品牌、產品、API、協定、版本、CLI 指令、參數、路徑、檔名、程式碼、欄位名、識別碼、錯誤碼、數值與格式字串。

範例：`Docker`、`GitHub`、`CI`、`docker build`、`--no-cache`、`/var/log`、`REQ-123`、`REP_B02`、`if (healthcheck)`。

## 情境式術語示例

以下示例須依上下文判斷，不得逐字或機械替換。

- deployment readiness [部署準備程度]
- Docker workflow [Docker 工作流程]
- CI/CD [持續整合／持續交付]
- smoke test [冒煙測試]
- regression test [回歸測試]
- integration test [整合測試]
- health（服務或系統狀態）[健康狀態]
- health check [健康檢查]
- artifact [建置產物]
- pipeline [流水線]
- rollback [回復至先前狀態]
- port [連接埠]
- logs [日誌]
- read-only [唯讀]
- prompt [提示詞]

## 專有名詞與語意邊界

- 不得修改專案、服務、品牌、產品、API、協定、版本、CLI 指令、參數、路徑、檔名、程式碼、欄位名、識別碼、錯誤碼、數值與格式字串。
- 不得將不可拆解的專有名詞硬譯成中文；可保留英文並加上中文說明。
- 只在一般敘述文字中處理英文功能詞；不得變更命令、程式碼、名稱、引用或其他受保護片段。
- 術語翻譯必須符合句中技術意義，不得改變事實、條件或邏輯。

## 驗收

- 確認可中文化的一般敘述英文已處理，且不殘留不必要的英文功能詞。
- 確認命令、程式碼、識別碼、路徑、數值、版本與條件邏輯保持不變。
- 確認專有名詞可辨識，修訂後文字可直接閱讀。

## 輸出

直接輸出完整修訂版；必要時附上高風險術語的詞彙對照。
